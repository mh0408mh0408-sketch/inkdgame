# 🎨 インク de リンク！ Online

ボードゲーム『スタンプ絵作りクイズ インク de リンク！』を、ブラウザで 2〜8 人が協力プレイできる Web アプリです。
身内で遊ぶ用の非公式ファンメイドです。サーバーは Firebase Realtime Database を使うので、**自前のサーバー不要・静的ホスティングだけで動きます**。

## 遊び方

1. 全員が同じ URL を開く
2. 1 人が「名前」と「合言葉」を入れて **部屋を作る（ホスト）**。他の人は同じ合言葉で **部屋に入る**
   - ロビーの「招待リンクをコピー」を使うと、合言葉入りの URL を共有できます
3. ホストが「ゲーム開始」。全 5 ラウンド、ラウンドごとにキャプテン（回答者）が交代します

| ラウンド | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| スタンプ上限 | 5 | 4 | 3 | 2 | 1 |

- **画家**：お題を見てスタンプ（赤丸・青四角・緑三角・黄棒）だけで絵を作って提出
- **キャプテン**：絵を見て、シートごとにお題カードを割り当てて確定
- 累計ミスが **プレイヤー人数を超えたら敗北**、人数以内でラウンド 5 を終えれば **全員勝利**
- 2 人プレイは画家 1 人がキャンバス 2 枚、3 人プレイは画家 2 人で計 3 枚を担当
- 「はみ出し者」ルール ON で、予想時にダミーのお題カードが +2 枚混ざります

### 🔁 連戦モード
- 勝敗は部屋ごとに **通算成績（○×・連勝数）** として記録されます
- 結果画面でホストが「同じメンバーでもう1戦！」を押すと、すぐ次のゲームが始まります（最初のキャプテンは毎回ずれます）
- 連戦中は出たお題を避けて出題し、使い切ったら自動で巡回します
- ロビーで「成績をリセット」できます

### 操作のコツ
- **PC**：キャンバスをクリック/ドラッグで仮置き、ホイールで回転、ダブルクリックで押印。キャンバスの端からのはみ出し押しも OK
- **スマホ**：タップで仮置き → 十字キーと角度ボタンで微調整 → 「ここにスタンプを押す！」
- 「シート縦横切替」は紙ごと 90 度回すので、描いた内容も一緒に回ります
- **キャプテン**：お題カードをシートへドラッグ、またはカードをタップ→シートをタップ、プルダウンでも割り当てできます

### 切断・リロード
- リロードしても自動で元の部屋・席に戻ります
- 別の端末から戻る場合は、**同じ名前**で「部屋に入る」を押すと、切断中の自分の席を引き継げます
- ホストが切断すると、オンラインの最古参プレイヤーが自動でホストを引き継ぎます
- ゲーム途中の新規参加はできません

## ファイル構成

```
index.html              画面（マークアップ）
css/style.css           スタイル
js/app.js               ゲーム進行・同期・UI
js/draw.js              スタンプ／シートの描画
js/words.js             標準お題（100語）
js/firebase-config.js   Firebase の接続設定
database.rules.json     Realtime Database のセキュリティルール
```

ビルド不要の素の HTML / ES Modules です。

## ローカルで動かす

ES Modules を使うため、`file://` で直接開かず簡易サーバー経由で開いてください。

```powershell
# Python がある場合
python -m http.server 8000
# → http://localhost:8000
```

同一ブラウザで複数タブを開けば 1 人で動作確認できます（タブごとに別プレイヤー扱い）。

## Firebase の準備（自分のプロジェクトを使う場合）

同梱の設定は作者のプロジェクトです。**自分で用意する場合**：

1. [Firebase コンソール](https://console.firebase.google.com/) でプロジェクトを作成
2. **Realtime Database** を作成（ロケーションは任意）
3. プロジェクト設定 →「マイアプリ」→ Web アプリを追加し、表示された設定を [`js/firebase-config.js`](js/firebase-config.js) に貼る
   - データベースのリージョンが `us-central1` 以外なら `databaseURL` も追加してください（ファイル内コメント参照）
4. Realtime Database →「ルール」に [`database.rules.json`](database.rules.json) の内容を貼って公開

> [!IMPORTANT]
> 「テストモード」のままだと **30 日で書き込みが拒否されます**。必ず上のルールに差し替えてください。
> このルールは「部屋の一覧を取得できない／合言葉（部屋 ID）を知っている人だけが読み書きできる」という設定です。

## GitHub Pages で公開する

1. GitHub で新しいリポジトリを作成（公開／非公開どちらでも可。ただし無料プランで Pages を使うなら公開リポジトリ）
2. このフォルダで：
   ```powershell
   git add .
   git commit -m "Initial commit"
   git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
   git push -u origin main
   ```
3. GitHub のリポジトリ → **Settings → Pages** → Source を **Deploy from a branch**、Branch を `main` / `/ (root)` にして Save
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で遊べます。この URL を身内に共有してください

## セキュリティについて（身内向けの割り切り）

- Firebase の Web `apiKey` は秘密情報ではないため、公開リポジトリに置いても問題ありません。守りの要は上記の **データベースルール** です
- 認証を入れていないため、**合言葉を知っている人は誰でも部屋に入れ、データも読めます**（画家のお題も、技術的には開発者ツールで見えます）。推測されにくい合言葉を使い、身内以外には教えないでください
- 終了した部屋のデータは自動削除されません。気になる場合は Firebase コンソールの `rooms` から削除してください
